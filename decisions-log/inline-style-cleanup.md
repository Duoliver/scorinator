# Inline-style cleanup — decisions log

A two-part cleanup replacing `style` props with CSS Modules and shared tokens, condensed here from the running Decisions log in `PROGRESS.md` — see that section for the procedure this follows.

- **2026-09-10 (first step):** The user asked to start cleaning up inline styles, beginning with page and section headings (`h1`/`h2`). `design-system/tokens/elements.css` now holds a global rule for each, using two new tokens (`--font-size-3xl`, `--font-size-4xl`, `tokens.css`), imported once from `main.tsx`. Every existing `<h1>`/`<h2>` in the app dropped its repeated inline `style` prop. `DESIGN_SYSTEM.md` documents the rule and its one boundary: only a heading with zero per-instance variation belongs in `elements.css`; a genuine one-off override should use a class or a different element, not grow this file into per-case exceptions. This is a first step, not a full inline-style cleanup — `App.tsx`, `TeamForm.tsx`, `Table.tsx`, and `TeamsScreen.tsx` still use `style` props elsewhere, flagged when `coding-standards.md`'s "No inline styling" rule was first added.

- **2026-09-10 (continued):** The user asked to continue the cleanup started with the `h1`/`h2` rule. `TeamsScreen`, `TeamForm`, `LeagueSetupScreen`, `DetailsStep`, `ReviewStep`, `TeamsStep`, and the outer `App.tsx` shell each gained a sibling `.module.css` file. Every `style` prop in those files is gone, except the one case `coding-standards.md` already allows: a value computed at runtime from data. Three files still set a colour swatch background from a team's `colour` field this way, since that value cannot be a static class. `Table.tsx` (`design-system/`) keeps its one `style` prop too — `gridTemplateColumns`, built from column widths passed in as props, the same kind of exception.

  Two calls made along the way, neither asked about: literal values that already matched an existing token exactly (`0.75rem` = `--space-3`, `0.875rem` = `--font-size-lg`, a hardcoded `2px` border that equals `--border-width`, and so on) now reference that token, with no visual change. Values with no exact token match (`1.375rem`/`1.75rem` gaps, a `1.125rem` swatch size) stayed as literal `rem` in the new `.module.css` files, unrounded — changing those would shift real layout by a pixel or two, which this pass did not set out to do. Left untouched, on purpose: the dev-only `Playground` inside `App.tsx` (already flagged for retirement once Task 17 lands) keeps its inline styles, since investing in a CSS module for code about to be deleted has little payoff. 256 tests, `type-check`, `lint`, and `build` all stay clean.
