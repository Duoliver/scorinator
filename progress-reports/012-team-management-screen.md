# Task 12 — Team Management screen

**What was built:** `features/teams` holds a `TeamsScreen`. It lists teams by colour swatch, name, tier badge, and slug. It has a create/edit drawer, `TeamForm`, with a live slug preview and a tier select. CSV import and export go through a thin `csvIO.ts` seam to `adapters/csv` and `adapters/tauri-fs`. `App.tsx` now mounts `TeamsScreen` above the old design-system playground. The playground stays, collapsed, below it. `Input` gained a `readOnly` prop for the slug field. It had none before.

**Test approach:** This task used Testing Library integration tests, per the `features/` row of `tdd.md`. Tests mount `TeamsScreen` and `TeamForm`. They exercise real calls into `engine/identity`, `importMerge`, and `adapters/csv`. Only the file-dialog boundary uses a mock. `vi.spyOn` covers the two `csvIO` functions, since no real OS dialog can run inside a test. `importMerge.ts` holds the slug-filling and upsert-by-slug logic. `csvIO.ts` holds the dialog and file-system wiring, through injected `FileSystem`/`SaveFileDialog` fakes. Each got its own unit tests first. All 211 tests in the repo pass. `type-check` and `lint` both come back clean.

**Decisions made:** The user confirmed two calls before build start. The decisions log in `PROGRESS.md` records both. Colour uses a plain hex input, not the MVP3-locked 16-swatch palette. The screen mounts standalone, with no nav shell. Beyond those two:
- CSV import upserts by slug into the current in-memory roster. A new slug appends. A matching slug overwrites that team in place. This does not replace the list outright. The MVP1 user story reads "so that I don't have to manually re-enter teams I already have" — a direct quote, and an additive story, not a replace-everything one.
- A blank Slug column from `parseTeamsCsv` gets a value from `slug(name)` at import time. The decision log of Task 11 named this exact wiring gap and assigned it to this task.
- Edit mode tracks the team under edit by its list index, not its slug. This mirrors the `editIndex` approach the prototype already uses on its own. It also avoids a case where a rename changes a slug mid-edit. `slug()` still does no cross-roster dedup, per Task 11. This task does not change that.
- The screen has no delete action. No MVP1 user story asks for one.
- The form has no OVR field. OVR rolls at season start, not at team creation. This screen writes only `slug`, `name`, `colour`, and `tier`.

**What is left, what is next:** Team state lives only in the memory of the screen itself. It does not yet wire to the `SavedTeam` shape in `adapters/json-io`. Full save/load is Task 17. A real nav shell and `preact-router` wait for whichever task first needs a second working screen. Task 13, League Setup, is the likely candidate. Tests exercise the CSV round trip only through the mocked `csvIO` boundary. The real Tauri save/open dialog still has no verified click-through in this sandbox. It has no display. This is the same open item Task 21 already flagged.
